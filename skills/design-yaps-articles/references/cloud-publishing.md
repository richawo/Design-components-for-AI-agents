# Hosted Design Yaps publication

The publishing worker authors and reviews through the existing GitHub connection.
Cloudflare Workers Builds is the authorized full-source executor. Its existing
private deploy key fetches the whole private repository, including large images.
No new token or permission is required.

## Prepare the batch

Read both repository instruction files, this skill, current editorial rules,
queue, published owners, docs and draft inventory. Follow Richard's editable Page
queue. Inspect five to ten actual leading result pages for each selected owner,
verify primary facts, retain original worked evidence and complete all 29
additional dictionaries with stable published slugs. Inspect candidate desktop,
phone and RTL layouts. Count already published owners on the London date; five
is a ceiling across retries. Repair existing factual issues first.

Read a complete pinned private recursive Git tree. Reject truncation, duplicate
paths, symlinks and missing inputs. `publicationInputsFromGitTree(tree)` computes
the same SHA-256 fingerprint as Cloudflare's actual source-byte inspection. The
records use sorted publication paths and their Git blob identities. Keep exact
article, current rulebook and review SHA-256 values in the private approval.

Editorial and localization rules must pass. R29 can be pending only in its
explicit build phase with the five mandatory executor stages named. R30/R37 can
be pending only for delivery, with the request identity, required live checks
and a concrete failure plan. These are not completed results. Save immutable
pre-publication approvals and separate final delivery evidence.

Commit selected private files and `_site/publication/approved-batch.json`, scope
`prepublication`, preserving concurrent work. Never force-push or overwrite
unrelated paths. An authenticated local checkout can run
`npm run publication:request` after its publication inputs are committed. A hosted
worker can form the same version-2 JSON from its committed approval, pinned
private revision and tree fingerprint. Commit only that public
`publication/content-request.json` signal to request the existing pipeline.

## Prove execution and delivery

Read the exact public request commit's GitHub check-runs. Require successful
`Workers Builds: design-yaps`, preserving its real build URL and result. The
`cf:build` wrapper executes source/locales audit, strict generation, types, full
tests and production build sequentially. Only success writes the matching
receipt; `cf:deploy` refuses a request without it and applies unchanged budgets.
A queued build, schedule or commit is not delivery. Retain failures and repair
the cause before resuming the same uncertain request.

Verify the matching `editorialRequest` in the live build marker, every affected
HTML/Markdown edition, metadata and visible structured data, images, internal
links, feeds/sitemaps, MCP reads and anonymous Pro guards. Prove source equivalence
if an unrelated descendant deploys during verification. Do not call a batch
delivered before these checks pass. IndexNow proves neither indexing nor ranking.
Review the maintained official Google inventory at least weekly.

## Connector limits and scope

The optional connected-source materializer rejects missing, corrupt, extra or
unsafe files and records exact source identities. It is not Git authentication.
Never run `pro:sync` on a connector snapshot. The 22 October preflight found five
legacy PNG originals over 1 MiB unavailable through the connected reader. Do not
omit them and claim a full local build. Use the complete Cloudflare executor.

The Page controller maintains its Page. Actual publication belongs to a worker
whose saved request explicitly authorizes publication to the target repositories.
Page maintenance text alone does not expand that authority. Preserve connector
approval rejections; do not bypass them by copying credentials or retrying a
broader operation. Report the exact missing authorization when unresolved.
