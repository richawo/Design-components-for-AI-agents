# Floating Label Field

Build one text field for React 19 with Tailwind v4 and motion/react (plus lucide-react for the mail glyph in the demo). The label lives inside the field. When the field is focused or filled, the label rises onto the top hairline and the border opens a notch around it, so the label reads as part of the frame rather than a tooltip. The field is a native `<input>` that takes every normal input prop. Validation is opt-in. Dark first, monochrome, with error and success as the only colours.

**Layout.** Root is a `@container` block, `max-width: 420px`, full width below that. The field is 56px tall (md) or 64px (lg), `border-radius: 12px`. Horizontal padding is 16px (md) or 18px (lg). The leading slot is measured: its width plus a 10px gap moves the label, the notch start and the input's left padding. The trailing slot is measured the same way and sets the input's right padding. A text suffix sits in the trailing slot, and the success tick sits beside it at a 10px gap. Below the field, 10px down, the helper row takes the message on the left and the count on the right, with the same horizontal padding as the field. The count reserves its width from the start, so the message never reflows when the count appears.

**Typography.** Input and label use the sans role. Input text is 16px (md) or 18px (lg), which keeps iOS from zooming. The resting label is 15px (md) or 17px (lg), centred vertically in a 20px line box. The floated label is the same text scaled to 0.76, transform origin left centre, so it never re-lays out. Helper, error and success text are 13px with leading 1.45, becoming 13.5px at `@sm`. A text suffix is 13px in the muted colour. The count is mono 12px with tabular figures.

**Colour (dark).** Surface `#0b0b0c`. Ink `#f4f4f5`. Hairline `rgba(244,244,245,0.14)`, hover `0.30`, focus `0.90`. Muted text `0.58`, icon `0.42`. Error `#f0937a`. Success `#8fd7a6`. Light theme inverts to `#ffffff` surface, `#111113` ink, `#b3432a` error and `#2c7a45` success. The count is ink when it appears and turns to the error colour at the limit. Focus and state colour live on the border (see the notch), so there is no outer focus ring.

**The notch.** The border is a separate absolutely positioned layer with an inset box-shadow, masked with three layers: a left strip `0 0 / var(--ifl-nl) 2px`, a right strip starting at `var(--ifl-nr)`, and the body below 2px. The notch runs from `labelX − 4px` to `labelX + measuredWidth × 0.76 + 4px`. Write `--ifl-nl` and `--ifl-nr` imperatively from motion's `animate` so the cut moves on the animation frame without re-rendering React. The cut never reaches the corner, because the gap is 4px and the radius is 12px.

**Border states.** Rest: 1px hairline at 0.14. Hover: 1px at 0.30. Focus-within: 1.5px at 0.90, drawn on the masked border so the line opens around the label. Error: 1.5px in the error colour. Success: 1.5px in the success colour. Disabled: 1px hairline, no hover response. Do not add an outer outline, halo or glow.

**Motion.** Rise and notch share one 320ms ease-out `[0.22, 1, 0.36, 1]`. Reversing focus mid-flight reverses both edges from where they are. Helper, error and success text cross-fade inside `AnimatePresence mode="popLayout"` with a 6px offset and a 3px blur clearing over 260ms. The count rises in the same way when it appears, and its digits tween over 180ms. The success tick draws its path with `pathLength` over 420ms, 100ms after it mounts, and scales from 0.8 while it fades in. On first view the whole block rises 10px from a 6px blur over 600ms, once. Autofill: Chrome fills the field without firing a change event, so the component listens for the `ifl-autofill` keyframes that a `:-webkit-autofill` rule plays, reads the DOM value, and treats the label as floated.

**Reduced motion.** The label, notch, messages, count and tick take no transforms, offsets or blur. Colour and opacity changes run at 150ms or less, the notch is set instantly, and the tick is drawn already complete.

**Validation.** Validation is a prop, not a rule baked in. `validate(value)` decides whether a value is acceptable. The demo passes an email check: a local part, an `@`, a domain and a top-level domain of at least two letters. Without `validate` the field never shows an error or the success tick. With it, an invalid value is called out only after 800ms of rest or when the field is left. A valid value clears the error straight away and shows the success tick.

**Count.** Appears only once the value reaches 80% of `maxLength`, so a 22-character limit shows the count at 18. At rest, with no value near the limit, nothing shows. The input stops at `maxLength`.

**Disabled.** The native `disabled` attribute, or `state="disabled"`. The field and its helper row dim together to 42% opacity, the cursor is `not-allowed`, the border does not respond to hover, and the wrapper carries `aria-disabled`.

**Accessibility.** A native `<input>` that takes `type`, `name`, `autoComplete`, `inputMode`, `required` and `spellCheck` as passed. The label is associated with `htmlFor`, and the label is `pointer-events: none` so taps reach the input. `aria-invalid` is set in the error state. `aria-describedby` points at the message container, which is `aria-live="polite"`, so the error and success copy is announced once per change. `onFocus`, `onBlur` and `onChange` are composed with the internal handlers. Decorative layers, the prefix glyph and the tick are `aria-hidden`. Focus is shown on the border, which is a visible 1.5px line at 0.90 ink against the surface, and the field is keyboard-operable with no extra ring.

**Don't.** No Material floating-label clone with a filled background. No coloured fills, glow or gradient on focus. No outer focus ring running over the notch. No red warning triangle. No shake animation on error. No count before 80% of the limit. No label that jumps from one place to another instead of rising. No accent colour on the success state beyond the tick and its message. No emoji or sparkles in the field.
