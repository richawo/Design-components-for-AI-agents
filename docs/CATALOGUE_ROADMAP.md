# Catalogue roadmap: 68 → 218 components

Decided 2026-10-10. This is the build plan for roughly 150 new components, built in parallel by fast builder agents and reviewed by critic agents. Every row below is a brief, not a spec: builders still hold each component to `docs/COMPONENT_SPEC.md` (files, taste bar, slop list, interaction tokens, responsive, accessibility, visual QA) and to the cursor demo and live controls contract defined there.

**Ground rules for this expansion**

- **Everyday free, showpieces Pro.** Primitives (buttons, inputs, selects, toggles, tabs, overlays) are mostly free. AI-native, agent, shader and background, dashboard and complex section components are mostly Pro. Overall split: **60 free / 90 Pro (40 / 60)**.
- **One idea per component.** Each brief names the idea, the state it must show and what to avoid. If a builder can't find the idea in the brief, the brief is wrong: flag it, don't improvise a generic version.
- **Monochrome and dark first** as the spec says. "accent" in a control list always means the one brand accent prop, never a second palette.
- **Standard controls.** Every component also exposes `theme` (segmented: dark, light) where it supports both, and `replay` (action) to rerun its entrance and demo. The control lists below are the component-specific ones only.
- **Slugs are final.** All 150 are unique, kebab-case and checked against the 68 existing slugs.

**Placement rules** (to stop near-duplicates):

- A full-bleed animated field is `backgrounds`; a 3D object or scene is `three-d`. A shader hero is `hero`.
- One field is `inputs`; a choice control is `selects`; several fields with a submit are `forms`; sign-in flows stay in `auth`.
- Anything that floats above the page and dismisses is `overlays`; anything that reports a state is `feedback`; anything that measures toward a limit is `progress`.
- AI that talks to a person is `ai`; AI that acts (tools, plans, approvals, runs) is `agents`.
- React Native components stay in `mobile` (current spec rule). Their row below notes the web sibling they mirror where there is one. Moving mobile into functional categories with a platform filter is a later site decision, not part of this plan.

## 2. The 150 components, in 7 waves

Waves are ordered by value: the AI-native set and the most-searched primitives land first, long-tail marketing sections last. Within a wave nothing depends on anything else (every component is one self-contained file), so all rows in a wave can be built at once. Each wave is about 40% free and carries at most two or three WebGL components so critics can review previews without exhausting GPU contexts.

Legend: **F** free, **P** Pro, **RN** React Native. Controls use `name:kind(options)`; kinds are toggle, slider, select, segmented, color, text and action.

| 3 | 22 | 9 | 13 | Multi-agent, overlays, feedback states, first dashboard |

## 3. Items that need care

**Locale, time and dates.** Only `react`, `motion`, `lucide-react` and `three` are allowed, so date maths is hand-written. Use `Intl.DateTimeFormat`, `Intl.NumberFormat` and `Intl.Locale` week info (fall back to Monday) for every label, week start and number. Test DST transitions, 29 February and RTL layout in `date-picker-popover`, `date-range-presets`, `calendar-month-events`, `calendar-week-grid`, `scheduler-slots`, `chart-heatmap-calendar` and `mobile-date-strip`. Time zone switching in `scheduler-slots` must use `timeZone` options, never offset arithmetic.

**Keyboard models.** Tables, grids, trees and boards each have a specific ARIA pattern and they are easy to fake: `data-table-sortable` (aria-sort, roving focus), `data-grid-editable` (grid role, edit versus navigate modes), `file-tree` (tree role with typeahead), `kanban-board`, `card-swipe-deck` and `dock-magnify` (every drag needs a keyboard equivalent). Critics should test these with the keyboard before looking at the visuals. No virtualisation library is allowed, so demos cap rows and say so in usage.

**WebGL budget.** Browsers cap live WebGL contexts at around 16. The gallery and category pages must show static poster frames for shader and three-d components and mount the live canvas only in the focused preview. Each wave carries at most three WebGL components so critic sessions don't exhaust contexts. Every shader: DPR ≤ 2, IntersectionObserver pause, one still frame under reduced motion, full dispose on unmount.

**Overlays without portals.** No portal library: overlays position within the component's own container for previews and document how to lift them to `document.body` in usage. Focus trap, scroll lock, Esc, outside click and focus return are required on every dialog, sheet, drawer and menu.

**Custom cursors versus the cursor demo.** `cursor-morph`, `cursor-multiplayer`, `button-magnetic` and `tilt-parallax` react to the pointer, so the scripted demo cursor must drive the component's own pointer handlers rather than a separate overlay, or the demo will show nothing. Custom cursors never hide the system cursor on touch or under reduced motion.

**Fake data that must look fake.** `payment-card-form` is demo UI: format and Luhn-check only, no network, published test-style numbers, generic network monograms instead of trademarked logos. `api-keys-manager` keys are visibly fictitious. Logo walls, integration tiles and model pickers use fictional brands set in type, never real company marks.

**No network media.** Maps (`hero-dot-map`, `map-dot-pings`) embed a small land mask (aim under 20 KB). Media players (`video-player-chapters`, `audio-player-waveform`, `testimonial-audio-quote`) draw scenes and generate waveforms; any audio is muted by default.

**Near-duplicates to keep apart.** Critics should compare each of these pairs side by side: `ai-composer-minimal` vs `input-ai-prompt` (the free one stays clearly lighter), `toast-promise` vs `toast-stack`, `bento-live-cells` vs `bento-grid`, `card-swipe-deck` vs `mobile-swipe-deck`, `agent-approval-gate` vs `mobile-agent-approval`, `bg-dither-flow` vs `three-contour-terrain`, `hero-dot-map` vs `three-globe-arcs`.

**Pills.** `badge-status-set` and `agent-status-pill` must report state that changes what the user does next. Builders should not add decorative pills anywhere else in this wave plan.

**Recategorise existing components** once the new categories exist (category pages only; component URLs are unchanged): `toast-stack` → feedback, `button-hold-confirm` → buttons, `three-wave-field` → backgrounds, `pixel-agent-status` → agents, `dashboard-orders-table` → data. `command-palette` can stay in `ai` or move to `overlays`; that is a founder call.

### Retrofit order for cursor demos and controls

Start with the existing components whose value is invisible in a still screenshot and which get the most traffic:

1. `command-palette`: open with ⌘K, type a fuzzy query, arrow and run. Controls: theme, accent, defaultOpen, groups count.
